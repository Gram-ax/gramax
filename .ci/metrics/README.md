# Алёрты на длительность CI-задач

Этот механизм присылает **алёрт, если CI-задача выполнялась дольше заданного лимита** —
чтобы вовремя замечать задачи, которые начали «расползаться» по времени.

Алёрты приходят в общий чат **«Gramax Dev Alerts»** в **Яндекс.Мессенджере**.

Механизм безопасный: что бы ни случилось, **он никогда не валит пайплайн**.

## Как включить алёрт для задачи

Задайте на задаче одну переменную — `CI_JOB_MAX_DURATION` (лимит в секундах):

```yaml
tests:
  variables:
    CI_JOB_MAX_DURATION: "600"   # 600 секунд = 10 минут
```

Это **та самая переменная**, которая включает алёрты для задачи. Нет переменной — нет
отслеживания. Значение — целое число секунд.

Примеры уже настроенных задач:

| Задача | Файл | Лимит, с |
|--------|------|----------|
| `biome` | [`.ci/tests.yml`](../tests.yml) | 180 |
| `tests` | [`.ci/tests.yml`](../tests.yml) | 600 |
| `static-e2e-pw` | [`.ci/tests.yml`](../tests.yml) | 180 |
| `next-e2e-pw` | [`.ci/tests.yml`](../tests.yml) | 600 |
| `legacy-e2e` | [`.ci/e2e-legacy.yml`](../e2e-legacy.yml) | 600 |

> **Если у задачи свой `after_script`.** Хук подключён глобально через `default.after_script`.
> Собственный `after_script` задачи перекрывает глобальный — добавьте ссылку на общий хук,
> сохранив свои команды:
>
> ```yaml
> after_script:
>   - ./.ci/e2e/delete-repos.ts
>   - !reference [.ci-job-duration-metrics, after_script]
> ```

## Куда приходят алёрты

В один общий чат **«Gramax Dev Alerts»** в Яндекс.Мессенджере. Разработчику настраивать там
ничего не нужно — достаточно задать лимит через `CI_JOB_MAX_DURATION`.

Сами правила алёртов и доставка в чат настроены на стороне инфраструктуры/DevOps, не в этом
репозитории.

## Переменные

Главная — для разработчика:

| Переменная | Назначение |
|------------|------------|
| `CI_JOB_MAX_DURATION` | Лимит длительности задачи в секундах. Задаёт разработчик на задаче; включает алёрты. |

Остальные обычно уже настроены DevOps (трогать не нужно):

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `PUSHGATEWAY_URL` | Адрес сервиса, куда уходят данные о длительности | — |
| `PUSHGATEWAY_USERNAME` | Логин для доступа к сервису (если нужен) | — |
| `PUSHGATEWAY_PASSWORD` | Пароль для доступа к сервису (если нужен) | — |
| `PUSHGATEWAY_TIMEOUT_SECONDS` | Таймаут запроса | `10` |
| `CI_JOB_DURATION_METRICS_DEBUG` | Подробный отладочный лог | выкл. |

## Если что-то не работает

Механизм **best-effort**: при любой проблеме (нет лимита, сервис недоступен, ошибка отправки)
хук просто пишет предупреждение и завершается успешно — **задача и пайплайн не падают**.

Если алёрт не приходит, временно включите подробный лог:

```yaml
variables:
  CI_JOB_DURATION_METRICS_DEBUG: "true"
```

Хук начнёт писать диагностику. Адреса и пароли в логе маскируются — секреты не утекают.
